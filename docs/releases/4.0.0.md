# DiagnosticExplorer 4.0.0

Release source: `01e9be74ea305a8660fba596c34c36d6d3e02080`, the reviewed main
commit after PR #168. This release completes the functional upstream integration
against `f8dbb59` while retaining the fork's Realtime/Retro and Trace Scope views.

## Changes

- Unified realtime logging with bounded retention, replay and routing recovery;
  log4net remains in core, with separate MEL, NLog and Serilog adapters.
- Fluent property configuration, dynamic diagnostic roots and DI registration.
- Fenced collection drilldowns, contextual operations, projected event views,
  and retained subscriptions across process selection changes.
- Live structured and JSON previews with five-second refresh, keyboard/pointer
  interaction, stale-response cleanup and exact JSON numeric fidelity.

Hosting parity is [deliberately unported](../upstream-integration-status.md#decision-hosting-parity-is-deliberately-unported).
The topology remains DiagnosticService with remote agents. The release includes a
Docker image; existing native Windows collector hosting can reuse the ASP.NET Core
entry point without porting upstream SelfHost or WiX.

## Consumer migration and rollout order

1. Record the existing collector image digest or native installation path and preserve
   its configuration and Mongo data. Verify which consumers share the endpoint; an
   isolated 4.0 endpoint avoids disrupting legacy agents outside the selected rollout.
   Deploy and verify the 4.0.0 collector before upgrading agents.
2. Vendor the exact core and hosting release packages into the consumer's local package feed;
   change the consumer's `Directory.Packages.props` pins from `3.2.2` to `4.0.0`.
3. Migrate realtime log4net wiring from `DiagnosticAppender` to
   `RoutingDiagnosticAppender` with explicit routes. Preserve logger/severity
   selection, destination categories, layouts and Retro logging. A class-name
   replacement alone is insufficient; the configuration contracts differ.
4. Restore/build the affected consumers, then roll the selected environment's
   agents through its established procedure. Verify real log delivery, properties,
   drilldowns and Retro against the deployed collector.

The legacy realtime appender is intentionally not bridged to the new stream.
Do not upgrade packages alone and assume existing realtime logging still reaches
the viewer. Existing remote hub URLs remain valid; SelfHost is not required.

Rollback an affected agent with its previous packages and logging configuration
together. Reverting the collector also requires reverting upgraded agents; do not
put new agents behind an old collector. Keep Mongo data and volumes intact.

## Validation at release source

186 frontend tests passed; TypeScript, lint and production build passed (existing
lint/build warnings remain). Backend Release build passed without warnings or
errors; 489 tests passed with one explicit qualification test skipped. GitHub main
CI and container publication passed. Browser checks exercised real Angular with
simulated hub frames; they are not evidence of a consumer runtime rollout.

Release publication, collector deployment and consumer deployment are distinct
steps. Their execution evidence belongs in the rollout record, not in this feature list.
